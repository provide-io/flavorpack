# FEP-0003: Cross-Language Wire Format Specification

**Status**: Draft  
**Type**: Standards Track  
**Created**: 2025-01-08  

## 1. Introduction

This specification defines the protobuf-compatible wire format for PSPF/2025 serialization, enabling perfect binary compatibility across Python, Go, and Rust implementations without requiring runtime protobuf dependencies.

### 1.1. Requirements Language

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in RFC 2119.

### 1.2. Design Goals

1. Perfect binary compatibility across Python/Go/Rust
2. No runtime protobuf dependency required
3. Maximum performance with generated code
4. Build-time proto compilation with runtime independence
5. Support for frozen/slots Python classes and zero-copy Rust

## 2. Wire Format Compatibility

### 2.1. Protobuf Wire Format

All PSPF serialization MUST use protobuf wire format encoding:

- **Varint encoding** for integers (field numbers, lengths)
- **Little-endian** for fixed-size types
- **UTF-8** for string encoding  
- **Length-delimited** for bytes and strings

### 2.2. Field Number Assignment

Field numbers MUST be consistent across all languages:

```
Message Type       Field Range    Usage
-----------------  -------------  -----
Core types         1-15           Frequently used fields
Extended types     16-255         Less common fields
Reserved           256-2047       Future expansion
Private            2048-2^29-1    Implementation-specific
```

### 2.3. Encoding Rules

```
Type        Wire Type  Encoding Method
----------  ---------  ---------------
int32       0          varint (signed)
int64       0          varint (signed)
uint32      0          varint (unsigned)  
uint64      0          varint (unsigned)
fixed32     5          4-byte little-endian
fixed64     1          8-byte little-endian
bool        0          varint (0 or 1)
string      2          length-delimited UTF-8
bytes       2          length-delimited
```

    _FIELD_NUMBERS = {'id': 1, 'offset': 2, 'size': 3, 'operations': 4}
    _FIELD_TYPES = {'id': 'varint', 'offset': 'varint', 'size': 'varint', 'operations': 'varint'}
    
    def to_bytes(self) -> bytes:
        """Serialize using wire format."""
        return encode_message(self)
    
    @classmethod
    def from_bytes(cls, data: bytes) -> 'SlotEntry':
        """Deserialize from wire format."""
        return decode_message(cls, data)

### 4.2. Wire Format Utilities

Pure implementations without protobuf runtime:

```python
# Python wire format utilities
def pack_varint(value: int) -> bytes:
    """Pack integer as protobuf varint."""
    result = bytearray()
    while value >= 0x80:
        result.append((value & 0x7F) | 0x80)
        value >>= 7
    result.append(value & 0x7F)
    return bytes(result)

def unpack_varint(data: bytes, offset: int = 0) -> tuple[int, int]:
    """Unpack protobuf varint, return (value, next_offset)."""
    result = 0
    shift = 0
    pos = offset
    
    while pos < len(data):
        byte = data[pos]
        result |= (byte & 0x7F) << shift
        pos += 1
        if not (byte & 0x80):
            return result, pos
        shift += 7
    
    raise ValueError("Incomplete varint")

def encode_message(obj) -> bytes:
    """Encode object using protobuf wire format."""
    output = bytearray()
    
    for field_name, field_num in obj._FIELD_NUMBERS.items():
        value = getattr(obj, field_name)
        if value == 0:  # Skip default values
            continue
            
        # Encode field number and wire type
        tag = (field_num << 3) | 0  # Wire type 0 for varint
        output.extend(pack_varint(tag))
        
        # Encode value
        output.extend(pack_varint(value))
    
    return bytes(output)
```

## 5. Binary Compatibility Requirements

### 5.1. Cross-Language Tests

Implementations MUST pass compatibility tests:

```python
def test_cross_language_compatibility():
    # Python creates message
    slot_py = SlotEntry(id=1, operations=pack_operations([BUNDLE_TAR, COMPRESS_GZIP]))
    data = slot_py.to_bytes()
    
    # Go reads message
    slot_go = go_deserialize_slot(data)
    assert slot_go.id == 1
    assert slot_go.operations == slot_py.operations
    
    # Rust reads message  
    slot_rust = rust_deserialize_slot(data)
    assert slot_rust.id == 1
    assert slot_rust.operations == slot_py.operations
    
    # All three produce identical binary output
    assert go_serialize_slot(slot_go) == data
    assert rust_serialize_slot(slot_rust) == data
```

## 7. Error Handling

### 7.1. Parsing Errors

```
Error Code  Description              Recovery Action
----------  -----------------------  ---------------
0x3001      Invalid varint encoding  Reject message
0x3002      Truncated message        Request retransmission
0x3003      Unknown field number     Ignore field (forward compatibility)
0x3004      Invalid wire type        Reject field
0x3005      String encoding error    Use replacement characters
```

### 7.2. Compatibility Errors

```
Error Code  Description              Action
----------  -----------------------  ------
0x3101      Version mismatch         Check compatibility matrix
0x3102      Unsupported field        Graceful degradation
0x3103      Required field missing   Use default value
0x3104      Type conversion error    Reject with clear error
```

## 8. Versioning and Evolution

### 8.1. Forward Compatibility

New proto versions MUST:
- Never reuse field numbers
- Add new fields with default values
- Mark removed fields as reserved
- Maintain wire format compatibility

```proto
message SlotEntry {
  uint64 id = 1;
  uint64 offset = 2; 
  uint64 size = 3;
  uint64 operations = 4;
  
  // Added in v1.1
  string description = 5 [default = ""];
  
  // Reserved from deprecated fields  
  reserved 6, 7;
  reserved "old_field_name";
}
```

### 8.2. Backward Compatibility  

Older implementations MUST:
- Ignore unknown fields
- Use default values for missing fields
- Continue functioning with new wire format
- Report version compatibility clearly
