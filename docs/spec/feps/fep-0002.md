# FEP-0002: Operation Chain System Specification

**Status**: Draft  
**Type**: Standards Track  
**Created**: 2025-01-08  

## 1. Introduction

This specification defines the composable archive operation chain system for PSPF/2025, enabling slots to use sequences of up to 8 operations from 255 available operation types. Operations can be chained in any compatible order to achieve complex transformations like TAR→GZIP→AES256→BASE64.

### 1.1. Requirements Language

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in RFC 2119.

### 1.2. Design Goals

1. Support 255 operation types with room for extensibility
2. Enable 8-operation chains in 64-bit packed format
3. Provide predictable left-to-right processing order
4. Support category-based operation organization
5. Enable validation and compatibility checking

## 2. Operation Categories

### 2.1. Category Ranges

Operations are organized in fixed 8-bit categories:

```
Range       Category         Description                Examples
----------  ---------------  -------------------------  -----------
0x00        NONE            No operation               -
0x01-0x0F   BUNDLE          Combine multiple files     TAR, ZIP, CPIO
0x10-0x2F   COMPRESS        Size reduction             GZIP, BZIP2, ZSTD
0x30-0x3F   ENCRYPT         Data security              AES256, ChaCha20
0x40-0x4F   ENCODE          Format transformation      Base64, Hex, ASCII85
0x50-0x5F   ZIP_VARIANTS    ZIP with specific methods  ZIP+DEFLATE, ZIP+LZMA
0x60-0x6F   COMPOUND        Other compound formats     7-Zip, RAR
0x70-0x7F   RESERVED        Future standard use        Reserved
0x80-0xFF   USER_DEFINED    Custom implementations     User extensions
```

### 2.2. Category Properties

Each category has specific properties:

```
Category    Can Bundle  Can Compress  Can Encrypt  Stream Safe
----------  ----------  ------------  -----------  -----------
BUNDLE      Yes         No            No           Yes
COMPRESS    No          Yes           No           Yes
ENCRYPT     No          No            Yes          Yes
ENCODE      No          No            No           Yes
ZIP_VARIANTS Yes        Yes           Varies       No
COMPOUND    Varies      Varies        Varies       Varies
```

## 4. Operation Chain Format

### 4.1. 64-bit Packed Format

Operation chains are packed in 64-bit integers:

```
Bit Offset  Size    Purpose
----------  ------  -------
0-7         8 bits  Operation 1 (applied first)
8-15        8 bits  Operation 2
16-23       8 bits  Operation 3
24-31       8 bits  Operation 4
32-39       8 bits  Operation 5
40-47       8 bits  Operation 6
48-55       8 bits  Operation 7
56-63       8 bits  Operation 8 (applied last)
```

### 4.2. Packing Algorithm

```python
def pack_operations(operations: list[int]) -> int:
    """Pack operations into 64-bit integer."""
    if len(operations) > 8:
        raise ValueError("Maximum 8 operations supported")
    
    packed = 0
    for i, op in enumerate(operations):
        if not (0 <= op <= 255):
            raise ValueError(f"Operation {op} out of range")
        packed |= (op & 0xFF) << (i * 8)
    
    return packed
```

### 4.3. Unpacking Algorithm

```python
def unpack_operations(packed: int) -> list[int]:
    """Unpack operations from 64-bit integer."""
    operations = []
    for i in range(8):
        op = (packed >> (i * 8)) & 0xFF
        if op != 0:  # Skip NONE operations
            operations.append(op)
        elif operations:  # Stop on first zero after ops found
            break
    return operations
```

### 4.4. Example Chains

```
Chain Description               Operations      Packed Value (hex)
-------------------------       -----------     ------------------
GZIP only                      [0x11]          0x0000000000000011
TAR then GZIP                  [0x01, 0x11]    0x0000000000001101
TAR, GZIP, AES256              [0x01, 0x11, 0x30] 0x0000000030111101
Complex 5-op chain             [0x01, 0x14, 0x02, 0x30, 0x40] 0x0000403002140101
```

## 5. Chain Processing Rules

### 5.1. Processing Order

Operations MUST be processed in strict order:

**Creation (Forward):**
```
Input Data → Op1 → Op2 → Op3 → ... → Op8 → Stored Data
```

**Extraction (Reverse):**
```
Stored Data → Op8⁻¹ → ... → Op3⁻¹ → Op2⁻¹ → Op1⁻¹ → Output Data
```

### 5.2. Operation Compatibility

Certain operation combinations are invalid:

```
Invalid Combinations          Reason
-----------------------       ------
Two bundle operations         Cannot bundle already bundled data
Compress then bundle          Bundle after compression loses efficiency
Encrypt then encode           Encoding should be outermost layer
```

### 5.3. Validation Rules

Implementations MUST validate chains:

1. **No duplicate operations** in the same chain
2. **Maximum one bundle operation** per chain
3. **Bundle operations first** (if present)
4. **Compression before encryption** (recommended)
5. **Encoding operations last** (if present)

## 7. Handler Interface

### 7.1. Operation Handler Protocol

All operation handlers MUST implement:

```python
class OperationHandler:
    def process(self, data: bytes, **params) -> bytes:
        """Apply operation to data."""
        pass
    
    def reverse(self, data: bytes, **params) -> bytes:
        """Reverse operation on data."""
        pass
    
    def validate_params(self, **params) -> bool:
        """Validate operation parameters."""
        pass
```

### 7.2. Chain Processor

```python
class ChainProcessor:
    def __init__(self, operations: list[int]):
        self.operations = operations
        self.handlers = [get_handler(op) for op in operations]
    
    def process(self, data: bytes) -> bytes:
        """Apply operation chain forward."""
        for handler in self.handlers:
            data = handler.process(data)
        return data
    
    def reverse(self, data: bytes) -> bytes:
        """Apply operation chain in reverse."""
        for handler in reversed(self.handlers):
            data = handler.reverse(data)
        return data
```

## 8. Error Handling

### 8.1. Validation Errors

```
Error Code  Description                Action
----------  -------------------------  ------
0x1001      Invalid operation value    Reject chain
0x1002      Too many operations        Truncate or reject
0x1003      Incompatible operations    Reject chain
0x1004      Unsupported operation      Use fallback or reject
0x1005      Missing handler            Load or reject
```

### 8.2. Processing Errors

```
Error Code  Description                Action
----------  -------------------------  ------
0x2001      Compression failed         Retry or use raw
0x2002      Decompression failed       Reject data
0x2003      Encryption failed          Reject operation
0x2004      Decryption failed          Invalid key or corrupt
0x2005      Format error               Data corruption
```

### 8.3. Recovery Strategies

1. **Graceful degradation**: Fall back to simpler operations
2. **Retry with validation**: Re-verify data integrity
3. **Alternative paths**: Try different operation sequences
4. **Error reporting**: Detailed failure information

## 9. Performance Considerations

### 9.1. Optimization Strategies

- **Streaming processing**: Avoid buffering entire datasets
- **Parallel processing**: Independent operations in parallel
- **Memory pooling**: Reuse buffers for large operations
- **Hardware acceleration**: Use CPU extensions where available

### 9.2. Benchmarking

Implementations SHOULD track:

```
Metric                  Target
--------------------    ------
Compression ratio       > 3:1 for typical data
Processing speed        > 100 MB/s on modern hardware
Memory usage           < 2x input data size
Chain validation       < 1ms for 8-operation chain
```

## 10. Extension Mechanism

### 10.1. User-Defined Operations (0x80-0xFF)

Users can implement custom operations:

```python
@register_operation(0x80)
class CustomCompression(OperationHandler):
    def process(self, data: bytes) -> bytes:
        # Custom compression logic
        pass
    
    def reverse(self, data: bytes) -> bytes:
        # Custom decompression logic
        pass
```

### 10.2. Plugin System

Implementations MAY support:
- Dynamic handler loading
- Configuration-based operation selection
- Runtime registration of new operations
- Versioned operation interfaces
