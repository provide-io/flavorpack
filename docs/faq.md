# Frequently Asked Questions

Common questions and answers about Flavor (Progressive Secure Package Format).

## 🤔 General Questions

### What is Flavor?
**Flavor (Progressive Secure Package Format)** is a modern package format designed for distributing Terraform providers with embedded runtimes, cryptographic signatures, and zero-dependency deployment.

### Why create a new package format?
Traditional terraform provider distribution has several challenges:
- **Dependency hell** - Complex runtime requirements
- **Security concerns** - No built-in signature verification
- **Platform fragmentation** - Different installation methods per OS
- **Air-gap deployment** - Difficult in restricted environments

Flavor solves these with self-contained, signed, cross-platform binaries.

### How does Flavor compare to Docker containers?
| Aspect | Flavor | Docker |
|--------|------|---------|
| **Size** | 20-60MB | 100MB+ |
| **Startup** | ~500ms | 1-3 seconds |
| **Dependencies** | None | Docker daemon |
| **Security** | Built-in signatures | Registry-dependent |
| **Air-gap** | Single file | Image + runtime |

### Is Flavor open source?
Yes! Flavor is released under the MIT license. Source code, documentation, and examples are all freely available.

## 🔒 Security Questions

### How secure are Flavor packages?
Flavor packages include multiple security layers:
- **ECDSA P-256 signatures** for authenticity
- **SHA-256 checksums** for integrity  
- **Tamper detection** built into the format
- **Reproducible builds** for supply chain security

### What happens if a signature is invalid?
Flavor tools will refuse to execute packages with invalid signatures:
```bash
❌ Package signature verification failed
❌ Flavor file is not trusted - aborting execution
```

### How do I rotate signing keys?
1. Generate new key pair: `flavor-packager keygen --out-dir ./new-keys`
2. Update CI/CD with new private key
3. Rebuild and release packages with new signature
4. Distribute new public key to users

### Can I use existing code signing certificates?
Currently Flavor uses ECDSA P-256 keys generated by `flavor-packager keygen`. Support for existing X.509 certificates is planned for future versions.

## 🏗️ Technical Questions

### What languages can I package with Flavor?
Currently Flavor supports:
- ✅ **Python** - Full native support with embedded runtime
- ⚠️ **Go** - Requires adapter layer (future enhancement)
- ❌ **Other languages** - Requires rewrite or bridge implementation

### How large are Flavor packages?
Typical package sizes:
- **Minimal Python provider**: 20-30MB
- **Standard provider with dependencies**: 40-60MB  
- **Complex provider with ML libraries**: 100MB+

The Python runtime contributes ~20MB to base size.

### What Python versions are supported?
Flavor currently embeds **Python 3.13+**. The embedded runtime includes:
- Standard library
- Common packages (requests, urllib3, etc.)
- Cryptographic libraries
- JSON/YAML processing

### Can I reduce package size?
Yes! See [Performance Tuning Guide](./performance-tuning.md) for optimization strategies:
- Remove unused dependencies
- Use lightweight alternatives
- Enable payload compression
- Optimize Python bytecode

## 🔧 Development Questions

### How do I debug a Flavor package?
Enable verbose logging:
```bash
# During build
PSPF_LOG_LEVEL=DEBUG flavor-packager build ...

# During execution  
PSPF_LOG_LEVEL=TRACE ./my-provider --verbose
```

Use dry-run mode to inspect without execution:
```bash
./my-provider --dry-run
```

### Can I extract contents of a Flavor package?
Use the info command to inspect without extraction:
```bash
flavor-packager info ./my-provider
```

For debugging, use force-extract:
```bash
./my-provider --force-extract --cache-dir /tmp/debug-cache
```

### How do I automate Flavor packaging in CI/CD?
Example GitHub Actions workflow:
```yaml
- name: Build Flavor package
  env:
    SIGNING_KEY: ${{ secrets.PSPF_PRIVATE_KEY }}
  run: |
    echo "$SIGNING_KEY" > private.key
    flavor-packager build \
      --out "./dist/provider_${VERSION}" \
      --payload-dir ./src \
      --package-key ./private.key \
      --public-key ./keys/public.key
```

See [CI/CD Integration Guide](./cicd-integration.md) for complete examples.

### What's the difference between Go and Rust implementations?
Both provide the same functionality with performance trade-offs:

| Implementation | Pros | Cons |
|---------------|------|------|
| **Rust** | 35% faster startup, 61% smaller binaries | Newer, less ecosystem |
| **Go** | Mature toolchain, familiar to many | Slightly slower, larger |

Rust is recommended for new projects.

## 🚀 Usage Questions

### How do I install Flavor tools?
See the [Installation Guide](./installation.md) for platform-specific instructions:
```bash
# Linux/macOS
curl -L https://github.com/your-org/flavor/releases/latest/download/flavor-linux-x86_64.tar.gz | tar xz

# Or build from source
git clone https://github.com/your-org/flavor.git && cd flavor && cargo build --release
```

### Can I use Flavor with existing Terraform workflows?
Yes! Flavor packages work as drop-in replacements:
1. Build your provider with Flavor
2. Place in terraform plugins directory
3. Use normally in terraform configurations

No changes needed to `.tf` files.

### How do I distribute Flavor packages?
Several distribution options:
- **Direct download** - Host on your website/CDN
- **GitHub Releases** - Attach to repository releases  
- **Terraform Registry** - Submit as official provider
- **Internal artifact registry** - Use corporate package managers

### What if terraform can't find my Flavor provider?
Check the provider installation:
```bash
# Verify binary is executable
ls -la ~/.terraform.d/plugins/*/my-provider
chmod +x ~/.terraform.d/plugins/*/my-provider

# Test provider directly
~/.terraform.d/plugins/*/my-provider --help

# Check terraform provider cache
terraform providers mirror ./mirror && ls ./mirror
```

## 🐛 Troubleshooting Questions

### "Package verification failed" - what's wrong?
Common causes:
1. **Key mismatch** - Build and verify using different keys
2. **Corrupted transfer** - Package modified during download
3. **Version mismatch** - Tools from different Flavor versions

Solution: Rebuild with matching keys and verify integrity.

### "Permission denied" when running package
Fix permissions:
```bash
chmod +x ./my-provider
```

On macOS, you may need to allow in Security & Privacy settings.

### Package startup is slow - how to optimize?
Performance optimization steps:
1. **Remove unused dependencies** from requirements.txt
2. **Use package caching** to avoid re-extraction
3. **Optimize Python bytecode** compilation
4. **Consider payload compression** settings

See [Performance Tuning](./performance-tuning.md) for detailed guidance.

### "Launcher not found" during build
Ensure flavor-launcher is installed and in PATH:
```bash
# Check if installed
which flavor-launcher

# Use absolute path if needed
flavor-packager build --launcher-bin /full/path/to/flavor-launcher ...
```
